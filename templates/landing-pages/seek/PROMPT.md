# Seek — an inspectable search product

Build a complete original search-product website named Seek. Its central promise is that someone can understand how a result was found, change the explicit rules, and inspect the original document. This is an interactive browser demonstration over ten fictional records. It does not create an external index, contact a provider, correct spelling, infer meaning, or perform AI retrieval. Keep this boundary visible in the guide, footer, product descriptions, and settings. Do not add production benchmarks, customer logos, fabricated testimonials, signup forms, billing, or implied external integrations.

Use this explanatory sequence, not their assets, movie dataset, purple identity, typography, wording, or source code. Use Geist for readable body and interface text, and Space Grotesk for headings and the wordmark. Serve licensed font files locally, retain their license text, and make the fonts usable without third-party requests. ## Exact matching and ranking contract

Normalize text with Unicode NFD, remove combining marks, lowercase it, and tokenize contiguous Unicode letters and numbers. Deduplicate normalized query words. Each query word becomes a group of alternatives when it belongs to a configured synonym group; otherwise it remains a group of one. Exact matching compares full normalized words. Enabled prefix matching also accepts indexed words beginning with an alternative. It does not reorder characters, perform edit-distance matching, stem words, or infer concepts. Make this distinction explicit in the guide and settings copy.

Search title, summary, and body paragraphs. In all-word mode, every query group must match somewhere in those fields. In any-word mode, at least one must match. An empty query browses the records permitted by facets. Eligibility is decided before ranking. For every matching group, award the configured title weight if it matches the title, the summary weight if it matches the summary, and one point if it matches the body. A group scores at most once in each field even if the word repeats. Add two points for an eligible record in the preferred topic, if one is configured. Sort total descending, optionally break ties by fixed sample updated date descending, then use stable record id. A preferred topic must never rescue a record that failed query or facets.

Defaults are title weight five, summary weight two, body weight one, all-word matching, prefix matching enabled, recent-date tie-breaking enabled, no preferred topic, and synonym groups search/find/lookup, export/download, and keyboard/shortcut. Preserve these concrete defaults in the form, preview, guide, exports, and reset behavior. The export-contract document and calmer-handoff story deliberately provide a useful ranking experiment: one matches export in its title and body, the other in its summary. Raising summary weight while lowering title weight changes their order without changing the underlying documents.

## Tuning workspace and validation

Use a two-column tuning layout: the larger left column is the actual settings form, and the right column previews saved rules. Group controls by matching, ranking, and explicit vocabulary. Matching uses a native select for all or any and a checkbox for prefixes. Ranking uses required integer number fields with title bounds one through eight and summary bounds one through five. Body is fixed at one and described in text. A topic preference select and recent-date checkbox follow. Keep all labels adjacent to their controls, and maintain enough vertical spacing that each setting can be scanned independently.

Synonyms use a multiline textarea with one comma-separated group per line. Ignore blank lines. Permit at most eight groups and two through six single-word terms in each group. Terms are limited to thirty characters. Reject multiword phrases, missing terms, duplicate normalized terms within or across groups, and malformed imported settings. Normalize valid terms before saving. An empty textarea means synonyms are disabled. Validation errors appear in a role-alert region, mark the textarea invalid where appropriate, and focus it so the error can be corrected. Do not partially apply a malformed configuration.

The preview is explicitly a saved-rule preview. Editing controls changes the unsaved status but does not secretly change the active engine. Saving first validates the entire form, then writes to the owned localStorage key seek-settings-v1. Only after a successful write does it apply the new configuration and refresh the preview and configuration JSON. If storage fails, retain previous applied settings and explain the failure. Invalid persisted data falls back to defaults. Restoring defaults resets only this product's owned configuration, not unrelated browser storage. Export validates the current form and may export a valid unsaved draft, with version and engine identifiers so the file's purpose is clear.

## Responsive behavior and accessibility

At narrow widths, reflow product interfaces into normal document flow. The marketing hero becomes a single column, keeping both headline and usable search panel. Do not scale the desktop panel down. Three-column explanation and query sections become vertical sections with full-width readable links. The filter rail becomes an accessible group above results; it does not vanish behind an unimplemented drawer. The settings preview moves after the form, and the record and guide rails move above their content. Tables and JSON wrap or scroll within their own containers without widening the page.

Keep body text around sixteen to eighteen pixels, actual controls and content at least fourteen, and secondary metadata at least twelve. Use visible focus outlines, native controls, sufficient color contrast, and meaningful accessible names. Do not put a custom role on ordinary links just to imitate an application widget. Slash focuses the primary search field only when focus is outside an input, textarea, select, or editable region. Escape clears the focused primary query while retaining facets. Tab follows normal document order and Enter activates native links or controls. A skip link becomes visible on focus.

Motion should reinforce hierarchy without withholding content. Use short opacity and vertical entrance transitions through IntersectionObserver only when reduced motion is not requested. All sections are visible in the initial document, so a failed observer does not hide the page. Hover transitions affect color, border, or a small arrow translation, never layout geometry. Disable nonessential animation and smooth scrolling under prefers-reduced-motion. No autoplay carousel, artificial loading delay, fake typing, or continuously shifting result order is necessary.
